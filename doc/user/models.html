Оглавление · Быстрый старт · Решение проблем

Провайдер задаёт адрес API и способ авторизации. У него может быть несколько моделей. Одинаковые идентификаторы у разных провайдеров относятся к разным подключениям.

Добавить или изменить провайдера#

Подготовьте базовый адрес API и сведения об авторизации.

  1. Откройте «Настройки → Провайдеры и модели».
  2. Нажмите «Добавить провайдера» либо ✎ в строке существующего провайдера.
  3. Заполните «Название» и «Адрес API (без /chat/completions)».
  4. Для Bearer заполните «Ключ доступа» самим ключом без префикса Bearer. Для другого способа выберите «Свой заголовок» и задайте его имя и значение.
  5. Проверьте «Провайдер включён» и нажмите «Сохранить».

Результат: подключение видно в списке. Пустое поле ключа при редактировании сохраняет прежний ключ; для замены введите новое значение. Сервис без авторизации может работать без ключа, даже если карточка сообщает «нет ключа».

Кнопка «Проверить» у провайдера проверяет получение списка моделей. При успехе появляется ✓ и число моделей; при ошибке — ✗, подробность доступна при наведении. Это не проверка ответа каждой модели. Если сервис не предоставляет список, добавьте модель вручную и отправьте тестовый запрос.

В примерах используются две модели DeepSeek: Flash и Pro. Для другого подключения укажите адрес и идентификаторы своего провайдера.

Добавить модель#

  1. Раскройте провайдера щелчком по его строке.
  2. Нажмите «Загрузить у провайдера». Откроется окно «⬇ Модели у …».
  3. Слева выберите вкладку по назначению: «💬 Для чата», «🧲 Эмбеддинги» или «📦 Прочие». Число на вкладке показывает, сколько на ней моделей, а при заполненном фильтре — сколько из них совпало.
  4. Найдите модель фильтром по названию или сортировкой. Щелчок по заголовку столбца сортирует по возрастанию, повторный щелчок — по убыванию.
  5. Нажмите «+ Добавить» в строке модели. Либо щёлкните строку и нажмите «+ Добавить» под вкладками. Модель для чата сначала проверяется, итог появляется под таблицей.
  6. В открывшейся форме «Модель» проверьте поля и нажмите «Сохранить». Только после этого модель попадает в набор и становится доступна в чатах. «Отмена» в форме возвращает к списку с той же вкладкой, фильтром и выбором.
  7. «Отмена» под вкладками закрывает список и возвращает к провайдерам.
  8. Если список недоступен, нажмите «Добавить вручную» в карточке провайдера и заполните форму «Модель».
СтолбецЧто показывает
«Название»Идентификатор модели у провайдера
«Тип»У моделей для чата — класс сложности по названию: 🟢 Простая, 🟣 Сильная, 🧠 Рассуждающая. У прочих — назначение: озвучка, распознавание речи, изображения и другие
«Окно контекста»Из списка провайдера. Со знаком ≈ — по названию модели, приблизительно
Кнопка строки«+ Добавить» открывает форму «Модель». Неактивная «✓ уже добавлена» — модель уже в наборе. Неактивная «+ Добавить» — модель добавить нельзя, причина под таблицей; «⏳ проверка» — идёт проверка

Знак «?» означает, что значение неизвестно. При сортировке такие строки стоят в конце в обоих направлениях. Прочие модели агенту не подходят.

Проверка вызова инструментов#

Модель для чата при выборе проверяется: умеет ли она вызывать инструменты. Без них агент только отвечает текстом и не может читать файлы, искать и работать с сервисами. Если провайдер сообщает это в списке моделей (так делает, например, OpenRouter), запроса нет. Иначе модели отправляется один короткий запрос с пробным инструментом, он может оплачиваться провайдером. Итог помнится до перезагрузки страницы.

Итог под таблицейЧто дальше
«✓ Модель вызывает инструменты»Добавить можно. В строке появляется отметка «с инструментами»
«✓ Модель вызывает инструменты разметкой в тексте ответа»Добавить можно: приложение выполняет такие вызовы
«Описание инструмента модель приняла, но ничего не вызвала»Добавить можно, поддержка подтвердится в работе
«⛔ Модель не вызывает инструменты»Добавить нельзя, выберите другую модель. В строке появляется отметка «без инструментов»
«⛔ Модель не отвечает на запросы чата»Добавить нельзя. В строке появляется отметка «не отвечает»
«⚠ Проверить вызов инструментов не удалось»Ниже указана причина: сеть, доступ, лимит или сбой сервиса. Добавить можно; «Проверить снова» повторяет запрос

Итог проверки повторяется в форме «Модель» над полями отчёта, в блоке «Проверка при выборе в списке». Окно контекста в форме подставлено из списка провайдера, иначе по названию модели. Первая сохранённая модель становится моделью по умолчанию для новых чатов.

Модель эмбеддингов на инструменты не проверяется. «+ Добавить» открывает её форму, см. Модель эмбеддингов.

При добавлении вручную проверка вызова инструментов сама не выполняется: нажмите «Определить» в редакторе модели.

Поля формы «Модель» (✎ у модели, «+ Добавить» в списке или «Добавить вручную»):

ПолеКак заполнять
«Идентификатор модели (уходит в API)»Точное имя, которое принимает провайдер
«Как называть в интерфейсе»Удобное название; можно оставить пустым
«Окно контекста»Подтверждённый предел модели; 0 означает, что он неизвестен
max_tokensМаксимальный размер ответа в токенах, поддерживаемый сервисом
«Температура»Параметр вариативности ответов; учитывайте возможности сервиса
«Назначение»«Чат» для обычной модели; «Эмбеддинги» — см. ниже
«Класс сложности»Подсказка в интерфейсе, не механизм автоматического выбора модели
«Заметка»Ваш комментарий о назначении модели

Окно контекста, подставленное по имени, приблизительно: проверяйте подпись источника под полем.

Проверить возможности модели#

  1. Нажмите ✎ у модели.
  2. Нажмите «Определить» рядом с «Окно контекста».
  3. Дождитесь отчёта о доступности, пределах и поддержке вызовов инструментов.
  4. Проверьте значения и сохраните форму.

Проверка отправляет короткие запросы и может оплачиваться провайдером. Некоторые сведения сервис не сообщает. Если модель отвечает текстом, но не поддерживает инструменты, задачи с чтением файлов или интеграциями могут не выполняться.

Некоторые модели пишут вызов инструмента в тексте ответа разметкой <tool_call>, если сервис не разбирает её сам. Приложение распознаёт такой вызов и выполняет его как обычный. Разметка остаётся в ответе, если вызов оборван или назван инструмент, недоступный в чате.

Модель эмбеддингов#

Модель эмбеддингов превращает текст в вектор чисел. Она нужна для поиска по смыслу в базе знаний и в чате не отвечает. Такие модели есть не у всех провайдеров: у OpenAI и OpenRouter есть (text-embedding-3-small), у DeepSeek нет. Можно подключить локальную Ollama с моделью bge-m3.

  1. Раскройте провайдера, нажмите «Загрузить у провайдера», откройте вкладку «🧲 Эмбеддинги» и нажмите «+ Добавить» в строке модели: откроется форма «Модель». Либо нажмите «Добавить вручную».
  2. В редакторе выберите «Назначение: Эмбеддинги». Для модели с вкладки «🧲 Эмбеддинги» оно выбрано само.
  3. Нажмите «Проверить». Приложение отправит две короткие контрольные фразы и покажет размерность, имя модели в ответе и расход.
  4. Нажмите «Сохранить». Без успешной проверки модель эмбеддингов не сохраняется: «Сохранить» проверяет её само.
ПолеКак заполнять
«Размерность»Длина вектора. Её выясняет проверка, вручную не задаётся
«Укоротить до (dimensions)»Пусто — вектор как отдаёт модель. Число — короче вектор, если модель умеет (OpenAI text-embedding-3): меньше места в браузере, поиск немного хуже
«Цена, $ за миллион токенов»Для оценки расхода. Подставляется из списка моделей провайдера (OpenRouter её называет) или проверкой, если провайдер сообщает стоимость запроса
«Префикс запроса», «Префикс документа»Только для моделей, обученных с пометками: у e5 это query: и passage: . Для остальных пусто

Векторы контрольных фраз сохраняются как отпечаток модели: по нему видно, та же ли модель отвечает под этим именем.

Базе знаний модель назначается в каталоге «📚 Знания»: Модель эмбеддингов базы. Удаление или правка модели, которой посчитана база, требует подтверждения: векторы базы удаляются или устаревают.

Модель эмбеддингов в карточке провайдера отмечена 🧲 и показывает размерность. Её нет в выборе модели чата, модели по умолчанию, служебной модели и модели плана. Модель по умолчанию нельзя перевести в эмбеддинги: сначала отметьте ★ другую модель.

Выбрать модель для чата#

Для новых чатов нажмите ★ у модели в настройках. Появится отметка «по умолчанию».

Для существующего чата:

  1. Откройте чат.
  2. Нажмите «+ модель» над полем ввода.
  3. Добавьте модель из нужного провайдера в набор чата и закройте окно.
  4. Щёлкните её название в панели чата.

Выбор применяется к последующим запросам. При смене провайдера история, включённая в следующий запрос, будет передана новому сервису. Изменение модели по умолчанию не следует использовать как способ переключения уже открытого чата.

Само приложение модель не меняет. При временном сбое оно повторяет запрос на той же модели. Если повторы не помогли, модель можно сменить кнопками «↻ На …» и «🔀 Другая модель…» в сообщении об ошибке, работа продолжится с места обрыва. Запасные модели для этих кнопок отмечаются в «Настройки → Надёжность»: Сбой провайдера и восстановление.

Две модели в одном чате#

Подключите обе модели к одному провайдеру либо к разным, затем добавьте их через «+ модель» в набор чата. Для следующего запроса выберите одну из них щелчком по названию над полем ввода.

Учебный сценарий:

  1. Выберите первую модель и отправьте: Предложи три пункта повестки рабочей встречи. Ответь кратко.
  2. Дождитесь окончания ответа и выберите вторую модель.
  3. Отправьте: Проверь предложенную повестку: назови один недостающий пункт и объясни почему. Ответь кратко.
  4. Найдите отметку «Модель изменена» в переписке и названия моделей под их ответами.

Вторая модель получает историю в пределах доступного контекста. Каждый запрос обрабатывает выбранная модель. Независимые ответы сравниваются в отдельных чатах с одинаковым запросом.

Удаление провайдера через 🗑 удаляет его модели и ключ. Сначала сохраните настройки в резервной копии, если они могут понадобиться.
